---
title: URL parameters
description: What a QueryLens link encodes, and how to build one by hand.
---

Every moment in the app — a query, a setting, a step — is reproducible from the URL alone. The app
writes it automatically (debounced, via `history.replaceState`, so stepping a trace doesn't fill your
back button with history entries), and the **Copy link to this step** button under the editor copies
the current one. This page is for building one by hand.

## Parameters

| Param | Meaning | Example |
|---|---|---|
| `q` | The SQL query | `q=SELECT * FROM users WHERE id = 5;` |
| `p` | Eviction policy — `lru` or `clock` | `p=clock` |
| `x` | Predict-then-reveal — `1` on, `0` off | `x=0` |
| `s` | The step to land on | `s=25` |
| `t` | Preset dataset — `users` (default), `orders`, or `logins`. Absent means `users`; an unknown value falls back to it | `t=orders` |
| `l` | Assignment lock — `l=1` seals the trace at step `s` until its prediction is answered (no skip, no scrubbing ahead); forces `x=1` | `l=1` |
| `d` | Custom row data, only present when the seed rows have been edited | *(generated, not hand-written — see below)* |
| `present` | `present=1` opens **presenter mode** — a full-viewport view of the current stage for a lecture hall, keyboard-driven, with prediction suppressed. `Esc` leaves it | `present=1` |
| `tour` | `tour=1` opens the **60-second tour** on load — five spotlights over the real interface, for a course link or a first walkthrough. `Esc` or *Skip* leaves it; it is not written back into the URL | `tour=1` |

A link that omits a parameter falls back to that setting's default, so the shortest working link is
just `?q=...`.

The [trace inspector](/trace) reads the same `q`, `p`, `d` and `t` keys, so a link copied from the
Playground opens there and shows the raw event stream for that exact query (it ignores `x` and `s` —
the whole trace is on one screen). Its `p` also accepts the three buffer-pool-only policies
(`fifo`, `second-chance`, `optimal`); the Playground still recognises only `lru` and `clock`. Add
`v=transcript` to open its numbered, printable prose view of the trace instead of the table.

## An example, assembled

```
https://query-lens.pages.dev/?q=SELECT%20*%20FROM%20users%20WHERE%20age%20%3E%2030%3B&p=lru&x=0&s=91
```

That's `age > 30` under LRU, prediction off, landing on step 91 — the first buffer eviction in that
trace. Remember to URL-encode the query string itself (spaces, `*`, `>` and so on).

## Limits

The URL is treated as untrusted input — it's the one value in the app that can arrive from a
stranger — so every field is capped and anything malformed or out of range falls back to the default
rather than erroring:

- **`q`**: 2000 characters
- **`d`** (custom rows): 500 characters per cell, 500 rows
- **`s`**: an integer from 0 to 100,000

## Custom row data (`d`)

Only appears once you've edited the seed data through **Edit data**, so a link to the default table
stays short. It's a generated, compact encoding — not meant to be written by hand — that round-trips
through the app: edit rows, copy the link, and reopening it reproduces exactly that table.

## Trace files

For a dataset too large to sit comfortably in a URL — or a bug report you want the seed data attached
to — **Download trace** (next to *Copy link to this step*) saves the same moment as a small JSON
file, and **Load trace** restores it. The file carries `sql`, `policy`, `predictOn`, `step`, the
edited `rows` (or `null`), and a build stamp. It deliberately does **not** store the event stream:
the engine is deterministic, so those re-derive exactly — use the [trace inspector](/trace)'s *Copy
JSON* if you need them frozen. It is parsed with the same suspicion as the URL — a field that is
missing, out of range, or a row that doesn't match the `users` schema fails the whole load rather
than half-applying it.
